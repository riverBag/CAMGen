You are a developer, and your task is to write a concise commit message based on the code changes in a target commit and one source of repository context.

The target code diff is the primary evidence. The repository context is auxiliary evidence for understanding the functional, behavioral, structural, or maintenance-level impact of the change.

Context information:

1. Evolutionary Exemplar Context: a similar historical commit, including its code diff and human-written commit message, which can help with project-specific terminology, intent expression, and commit message style.

Use the context to infer the change impact, but do not invent information that is not supported by the target diff or the provided context. If the context appears unrelated or insufficient, prioritize the target code diff. Do not mention the name of this context source in the final commit message. Do not copy the exemplar commit message unless it accurately describes the target change.

## Input Format:

--- START OF QUERY CODE DIFF ---
{QUERY_DIFF}
--- END OF QUERY CODE DIFF ---

--- START OF EVOLUTIONARY EXEMPLAR CONTEXT ---
=== START OF SIMILAR COMMIT ===

--- START OF SIMILAR CODE DIFF ---
{SIMILAR_DIFF}
--- END OF SIMILAR CODE DIFF ---

--- START OF SIMILAR COMMIT MESSAGE ---
{SIMILAR_MESSAGE}
--- END OF SIMILAR COMMIT MESSAGE ---

=== END OF SIMILAR COMMIT ===
--- END OF EVOLUTIONARY EXEMPLAR CONTEXT ---

## Output Format:

Output only one concise commit message describing the target code changes and their main intent or impact, wrapped in <message> </message> tags.

E.g. <message>Fix null handling when loading user configuration</message>
E.g. <message>feat(server): Add validation for registration requests</message>
